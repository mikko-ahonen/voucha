Building reliable business processes that span several systems is hard. Retry mechanisms and error handling are hand-written in each service, difficult to get right, and operations and testing are an afterthought.

voucha is an experiment in taking that burden out of application code. It keeps the process state, the record of every outbound call and the policy for resolving an unknown outcome in one transactional log, so that the application is reduced to small pure functions that decide what should happen next. It borrows the approach of databases and the transaction processing monitors of the mainframe era, modernized, on PostgreSQL.

What this does for you

  • You declare only the states and what happens on events. Locking, transactions, retries, idempotency keys, crash recovery and audit are provided by the runtime.
  • The "what if the call fails halfway" code is gone. Per external call you declare once whether a resend is safe, whether the other side can be asked, or whether an operator must decide.
  • A verified state machine. Unreachable states, dead ends and unhandled outcomes are compile errors, not incidents. voucha why tells you what is blocking a node.
  • Testing is cheap. Crashes mid-transaction, calls sent but never recorded, every interleaving, a hard kill of the process: the harness, fakes, simulator and fault points are built in.
  • The process can change while it runs. New work starts under the new definition; work in flight finishes under the old one.

Try it

git clone https://github.com/mikko-ahonen/voucha && cd voucha
clojure -T:build javac
clojure -X:test
bin/voucha dev voucha.example.batch/app

Requires a JDK and the Clojure CLI. PostgreSQL is embedded for development and tests.

Status

Experimental. Implemented and tested under crash, contention and fault injection, with no operating history yet. Expect interfaces to change.
